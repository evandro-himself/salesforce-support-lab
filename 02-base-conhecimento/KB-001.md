
# KB-001 — Erro de Cadastro Duplicado no Salesforce

**Plataforma:** Salesforce Sales Cloud  
**Objeto:** Account  
**Categoria:** Qualidade de Dados  
**Nível de suporte:** N1/N2  
**Status:** Solução documentada  
**Ambiente:** Trailhead Playground

## 1. Objetivo

Orientar analistas de suporte na identificação e
resolução de problemas relacionados ao bloqueio
de cadastros duplicados no Salesforce.

## 2. Sintoma

Ao tentar cadastrar uma nova conta, o usuário
recebe a mensagem:

"You can't save this record because a duplicate
record already exists. To save, use different
information."

O Salesforce impede a conclusão do cadastro.

## 3. Possíveis causas

- Já existe uma conta com informações semelhantes.
- Uma Duplicate Rule está configurada para bloquear
  registros duplicados.
- Uma Matching Rule identifica correspondências
  entre os dados informados e registros existentes.

## 4. Procedimento de diagnóstico — N1

1. Solicitar ao usuário o nome da conta.
2. Verificar a mensagem de erro apresentada.
3. Acessar o objeto Accounts no Salesforce.
4. Pesquisar por contas com nomes semelhantes.
5. Confirmar se o registro já existe.
6. Registrar as evidências no chamado.

## 5. Procedimento de diagnóstico — N2

Caso seja necessário investigar as configurações:

1. Acessar Setup.
2. Pesquisar por Duplicate Rules.
3. Identificar a regra aplicada ao objeto Account.
4. Verificar se Action On Create está como Block.
5. Conferir as condições de aplicação da regra.
6. Verificar a Matching Rule associada.
7. Analisar os critérios de correspondência.

Alterações em regras devem ser realizadas somente
por profissionais autorizados e após avaliação
do impacto sobre os demais usuários.

## 6. Solução recomendada

Se a conta já existir:

- Orientar o usuário a utilizar o registro existente.
- Verificar se os dados precisam ser atualizados.
- Evitar a criação de cadastros redundantes.

Se houver suspeita de bloqueio indevido:

- Registrar o cenário e as evidências.
- Encaminhar para análise N2 ou administração.
- Verificar os critérios de correspondência.
- Não desativar regras sem autorização.

## 7. Validação

Após a orientação ou correção:

1. Confirmar que o usuário consegue acessar
   o registro correto.
2. Verificar se não foram criadas novas duplicidades.
3. Registrar o resultado no chamado.
4. Documentar a solução aplicada.

## 8. Exemplo prático

No laboratório INC-005, foi configurada uma
Duplicate Rule para bloquear novos registros
cujo nome começa com LAB- e corresponde
exatamente ao nome de uma conta existente.

Ao tentar cadastrar novamente:

**Account Name:** LAB-Importacao Beta

O Salesforce identificou a duplicidade
e impediu o salvamento.

**Resultado:** bloqueio validado com sucesso.

- Pesquisar registros existentes antes de cadastrar.
- Preservar a integridade dos dados.
- Não desativar regras sem autorização.
- Registrar evidências dos problemas encontrados.
- Documentar procedimentos reutilizáveis.
- Encaminhar situações complexas ao suporte N2.
